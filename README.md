# 3xbot — учебный бот нейрофотосессий с оплатой

**3xbot** — минимальный, но рабочий пример Python-бота, который принимает фото пользователя, создаёт 4 AI-фотосессии через Replicate `openai/gpt-image-2` и продаёт генерации через ЮKassa.

Проект специально сделан без SDK Telegram, VK, MAX и Replicate: все интеграции идут обычными HTTP-запросами через `requests`. Так проще увидеть, как на самом деле устроены боты, платежи и генерация изображений.

## Что умеет бот

- Работает сразу в трёх мессенджерах: Telegram, ВКонтакте и MAX.
- Использует один общий сценарий диалога для всех платформ.
- Принимает фото пользователя и генерирует 4 изображения в случайных стилях.
- Сохраняет баланс генераций и платежи в SQLite (`bot.db`).
- Создаёт платежи в ЮKassa и автоматически проверяет их статус.
- Не требует публичного сервера: сообщения и платежи обрабатываются через polling.

**Polling** — это регулярный опрос API: бот сам спрашивает платформу, появились ли новые сообщения или изменился ли статус платежа. Это проще для обучения, чем **webhook** — публичный URL, на который платформа сама присылает события.

## Как устроен сценарий

1. Пользователь отправляет `/start`.
2. Бот показывает текущий баланс и просит выбрать пол.
3. Если на балансе нет генераций, бот предлагает тариф:
   - `Разовая — 100 ₽`: 1 фотосессия, то есть 4 изображения.
   - `Подписка — 499 ₽/мес`: 10 фотосессий на 30 дней.
4. Бот создаёт платеж в ЮKassa и отправляет ссылку на оплату.
5. После успешной оплаты бот начисляет баланс и просит фото.
6. Пользователь отправляет фото.
7. Бот списывает 1 генерацию, параллельно создаёт 4 изображения и отправляет результат.

## Архитектура

| Файл | Назначение |
|---|---|
| `bot.py` | Точка входа, long polling для Telegram/VK/MAX, отправка сообщений и фото |
| `dialog.py` | Общая логика диалога, не зависящая от мессенджера |
| `generator.py` | Генерация изображений через Replicate HTTP API |
| `styles.py` | Каталог стилей и prompt'ов для генерации |
| `payments.py` | Создание платежей и проверка статусов в ЮKassa |
| `db.py` | SQLite-хранилище баланса, подписок и платежей |
| `notifier.py` | Отправка уведомлений пользователю после оплаты |

**FSM** (finite-state machine, конечный автомат) в `dialog.py` хранит шаг пользователя: выбор пола или ожидание фото. Это простой и понятный способ описывать диалоговые сценарии.

## Требования

- Python 3.10 или новее.
- Аккаунт Telegram, если хотите запускать Telegram-бота.
- Сообщество VK, если хотите запускать VK-бота.
- Аккаунт MAX и бот в MAX, если хотите запускать MAX-бота.
- Аккаунт Replicate с API token для генерации изображений.
- Магазин ЮKassa для приёма платежей.

Можно запустить только одну платформу: например, заполнить только `TELEGRAM_TOKEN`, а поля VK и MAX оставить пустыми.

## Быстрый старт

```bash
git clone https://github.com/your-username/3xbot.git
cd 3xbot

python3 -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env
```

Если у вас команда называется `python`, а не `python3`, используйте `python`.

На Windows активация окружения обычно выглядит так:

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
```

**Virtual environment** (виртуальное окружение) — отдельная папка с зависимостями проекта. Она нужна, чтобы библиотеки этого проекта не конфликтовали с другими Python-проектами на компьютере.

После этого откройте `.env` и заполните нужные переменные.

## Переменные окружения

**Environment variables** (переменные окружения) — настройки, которые не хранятся в коде: токены, ключи API, ссылки и другие секретные данные.

| Переменная | Обязательна | Что указать |
|---|---:|---|
| `TELEGRAM_TOKEN` | Нет | Токен Telegram-бота от `@BotFather` |
| `VK_TOKEN` | Нет | Ключ доступа сообщества VK |
| `VK_GROUP_ID` | Для VK | Числовой ID сообщества VK |
| `MAX_TOKEN` | Нет | Токен бота MAX |
| `REPLICATE_API_TOKEN` | Да | API token Replicate |
| `YOOKASSA_SHOP_ID` | Для оплаты | Идентификатор магазина ЮKassa |
| `YOOKASSA_SECRET_KEY` | Для оплаты | Секретный ключ API ЮKassa |
| `YOOKASSA_RETURN_URL` | Для оплаты | HTTPS-ссылка возврата после оплаты |

Пример `.env`:

```env
TELEGRAM_TOKEN=123456789:AA...

VK_TOKEN=
VK_GROUP_ID=

MAX_TOKEN=

REPLICATE_API_TOKEN=r8_...

YOOKASSA_SHOP_ID=123456
YOOKASSA_SECRET_KEY=test_...
YOOKASSA_RETURN_URL=https://t.me/your_bot_username
```

Не публикуйте `.env`, `bot.db` и реальные токены в GitHub. Они уже добавлены в `.gitignore`.

## Как получить Telegram token

Официальная документация: [Telegram BotFather](https://core.telegram.org/bots/features#botfather).

1. Откройте Telegram и найдите `@BotFather`.
2. Отправьте команду `/newbot`.
3. Введите отображаемое имя бота, например `AI Photo Demo`.
4. Введите username бота. Он должен заканчиваться на `bot`, например `ai_photo_demo_bot`.
5. BotFather выдаст token. Скопируйте его в `.env`:

```env
TELEGRAM_TOKEN=ваш_токен
```

6. Откройте ссылку `https://t.me/your_bot_username`, нажмите Start и отправьте `/start`.

Важно: Telegram не разрешает двум процессам одновременно читать `getUpdates` одного и того же бота. Если увидите ошибку `409 Conflict`, значит этот же token уже используется где-то ещё.

## Как получить VK token

Официальная документация: [VK Bots Long Poll API](https://dev.vk.com/ru/api/bots-long-poll/getting-started).

1. Создайте сообщество VK или откройте уже существующее.
2. Перейдите в управление сообществом.
3. Откройте раздел `Работа с API`.
4. Создайте ключ доступа сообщества.
5. Дайте ключу права на сообщения сообщества.
6. Скопируйте ключ в `.env`:

```env
VK_TOKEN=ваш_ключ_сообщества
```

7. Найдите числовой ID сообщества. Его можно увидеть в настройках или в адресе API/сообщества. Укажите только цифры:

```env
VK_GROUP_ID=123456789
```

8. В разделе `Long Poll API` включите Long Poll и событие `Входящее сообщение`.
9. В настройках сообщений сообщества включите сообщения, чтобы пользователи могли писать боту.

**Long Poll API** — режим, в котором бот держит длинный HTTP-запрос к VK и получает новые события без публичного webhook.

## Как получить MAX token

Официальная документация: [MAX Bot API](https://dev.max.ru/docs-api).

1. Откройте MAX и найдите официального бота для создания ботов: `@MasterBot`.
2. Создайте нового бота по подсказкам MasterBot.
3. Скопируйте выданный token.
4. Укажите его в `.env`:

```env
MAX_TOKEN=ваш_токен
```

5. Запустите проект и отправьте боту сообщение в MAX.

MAX активно развивает Bot API. Если какой-то шаг в интерфейсе изменился, сверяйтесь с актуальной документацией по ссылке выше.

## Как получить Replicate API token

Официальная документация: [Replicate Python quickstart](https://replicate.com/docs/get-started/python).

1. Зарегистрируйтесь или войдите в Replicate.
2. Откройте страницу [API tokens](https://replicate.com/account/api-tokens).
3. Создайте новый token.
4. Скопируйте его в `.env`:

```env
REPLICATE_API_TOKEN=r8_...
```

В проекте используется модель `openai/gpt-image-2` на Replicate. Генерация изображений платная, поэтому проверьте баланс и лимиты аккаунта Replicate перед тестами.

## Как подключить ЮKassa

Официальная документация: [быстрый старт ЮKassa API](https://yookassa.ru/developers/payment-acceptance/getting-started/quick-start).

1. Зарегистрируйтесь в ЮKassa.
2. Создайте магазин. Для обучения можно использовать тестовый магазин.
3. В личном кабинете найдите `shopId` или `Идентификатор магазина`.
4. Найдите или выпустите `Секретный ключ API`.
5. Для тестов используйте тестовый ключ, который обычно начинается с `test_`.
6. Заполните `.env`:

```env
YOOKASSA_SHOP_ID=123456
YOOKASSA_SECRET_KEY=test_...
YOOKASSA_RETURN_URL=https://t.me/your_bot_username
```

`YOOKASSA_RETURN_URL` — ссылка, куда ЮKassa вернёт пользователя после оплаты. Для Telegram удобно указать ссылку на бота. Для VK или MAX можно поставить публичную ссылку на сообщество/бота или простую страницу с инструкцией вернуться в чат.

Как работает оплата в этом проекте:

1. Бот отправляет `POST /v3/payments` в ЮKassa.
2. ЮKassa возвращает `confirmation_url`.
3. Бот отправляет пользователю ссылку `confirmation_url`.
4. Пользователь оплачивает на стороне ЮKassa.
5. Бот раз в 10 секунд запрашивает `GET /v3/payments/{payment_id}`.
6. Если статус стал `succeeded`, бот начисляет генерации.
7. Если статус стал `canceled`, бот помечает платёж отменённым.

Для реального приёма платежей в РФ проверьте требования 54-ФЗ и онлайн-чеков. В этом учебном проекте объект `receipt` не отправляется, поэтому перед коммерческим запуском его нужно добавить под вашу юридическую схему.


## Проверка без оплаты

Для первого запуска проще проверить диалог без платежей:

1. Заполните только `TELEGRAM_TOKEN` и `REPLICATE_API_TOKEN`.
2. Запустите `python3 bot.py`.
3. Откройте бота в Telegram и отправьте `/start`.
4. Выберите пол.
5. Бот покажет тарифы, потому что баланс пуст.

Чтобы проверить генерацию без реальной оплаты, можно временно начислить себе 1 генерацию через Python-консоль:

```bash
python3
```

```python
import db
db.init()
db.add_credits("tg:123456789", 1)
```

Замените `123456789` на ваш Telegram chat id. Его можно увидеть в логах после первого сообщения боту.

## Частые ошибки

### `Не задан ни один токен в .env`

Вы не заполнили ни `TELEGRAM_TOKEN`, ни `VK_TOKEN`, ни `MAX_TOKEN`. Заполните хотя бы одну платформу.

### Telegram `409 Conflict`

Один Telegram token уже опрашивается другим процессом. Остановите второй запуск бота, сервер, Docker-контейнер или старый процесс.

### ЮKassa не включается

Проверьте, что заполнены все три переменные:

- `YOOKASSA_SHOP_ID`
- `YOOKASSA_SECRET_KEY`
- `YOOKASSA_RETURN_URL`

### Replicate вернул ошибку модерации `E005`

Модель может отклонить фото системой безопасности. В проекте генерация возвращается на баланс, чтобы пользователь не терял оплату из-за ошибки модели.

### VK не отвечает

Проверьте, что в сообществе включены сообщения, Long Poll API и событие `Входящее сообщение`.

## Почему код устроен именно так

Главный принцип проекта: логика диалога пишется один раз.

`dialog.handle(user_key, channel)` ничего не знает о Telegram, VK или MAX. Он работает с абстрактным `channel`, у которого есть методы:

- `send_text(text)`
- `send_buttons(text, options)`
- `send_photos(urls, caption)`
- `incoming.text`
- `incoming.photo_bytes()`

Каждый мессенджер в `bot.py` реализует этот интерфейс по-своему. Это позволяет добавлять новые шаги диалога в одном месте, а не копировать логику для каждой платформы.
